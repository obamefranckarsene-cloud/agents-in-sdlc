フィルターの実装、命令の更新、スキルの更新、品質保証 (QA) プロファイル、テストは、すべて 1 つのブランチに保存されています。まとめてレビューし、プルリクエストを開きましょう。星評価のプルリクエスト (PR) は自分でマージしましたが、今回は **Agent Merge** にマージ プロセスを任せます。

> [!NOTE]
> 通常は、機能、命令の更新、スキルの更新、QA エージェントを複数の PR に分けます。ワークショップを簡潔にするため、フィルターと品質ワークフロー全体を 1 つのセッションとブランチで進め、この PR にまとめました。

このレッスンでは、次のことを行います。

- Agent Merge と、マージ ライフサイクルを自動化する方法を学びます。
- 機能 PR 全体と検証の根拠を確認します。
- レビュー後にのみ Agent Merge を許可し、PR がマージされたことを確認します。

## シナリオ

フィルター機能の作業を通じて、Copilot を使って機能を計画、実装、検証しました。Tailspin Toys では、マージの許可を開発者の判断に委ねたまま、残りの PR 作業を自動化したいと考えています。

## Agent Merge とは

**Agent Merge** は、GitHub Copilot アプリでプルリクエストをマージするために必要な残りの作業を自動化します。有効にすると、アプリのセッションはプルリクエストを読み取り、CI チェックの失敗の修正、レビュー コメントへの対応、必要に応じたリベースなど、マージを妨げている問題を解決します。GitHub が許可するとマージを実行します。バックグラウンドで動作し、アプリの再起動後も続き、PR がマージされると自動的に停止します。

これまでは自分で **Merge pull request** を選択していました。Agent Merge にその作業を任せることもできますが、コードの編集やマージには、引き続き明示的な許可が必要です。マージ権限を与える前に、許可される操作と作業内容をレビューしてください。

## Agent Merge を使って PR を管理する

作成したコードをレビューできました。Agent Merge に PR プロセスを管理させましょう。

1. エージェント ピッカーで **Default agent** を選択します。
2. **Create PR** の横にあるドロップダウンを選択します。
3. **Agent Merge** を選択します。ボタンが **Agent Merge** に変わります。
4. **Agent Merge** ボタンを選択してプロセスを開始します。ドロップダウンのオプションを選ぶだけでは開始されません。

Agent Merge は次の作業を開始します。

- タイトルと説明を含むプルリクエストを作成します。
- issue からセッションを開始した場合は、PR の説明に関連する issue を記載します。
- リベースを行うか、ターゲット ブランチとのマージ競合に対処します。
- CI を監視し、すべてのチェックが成功するようにします。
- 他の開発者や Copilot コード レビューからのフィードバックがないか PR を監視し、コメントを解決するよう更新します。
- すべてが成功したら、必要に応じて PR を自動的にマージします。

すべてのチェックが成功したら、Agent Merge に PR のマージも任せます。

5. マージを許可する前に、PR の差分と検証の根拠をレビューします。
6. **Agent Merge** の横にあるドロップダウンを選択します。
7. **Merge pull request** の横にチェックが付いていることを確認します。
8. エージェントに明示的にマージを依頼します。

   ```plaintext
   Merge the PR once all required checks and approvals pass. Do not bypass repository protections.
   ```

9. 進捗を確認し、報告されたブロッカーを解消します。続行前に、PR の状態が **Merged** になっていることを確認します。マージ権限が有効になったことやエージェントの実行中表示だけでは、マージ完了の確認になりません。

> [!IMPORTANT]
> Agent Merge は、リポジトリの保護や権限不足を回避しません。続行前にそれらのブロッカーを解消してください。
