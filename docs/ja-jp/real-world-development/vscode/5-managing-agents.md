Copilot をエージェント モードで使うと、コードベースを調べ、変更を提案し、ファイルを編集し、コマンドを実行します。VS Code の Copilot Chat は、ユーザーのマシンでリアルタイムに実行される各ツール呼び出しやファイル編集を表示します。差分をインラインでレビューし、個々の変更を承認または取り消し、フォローアップ プロンプトを送って作業を調整または拡張できます。エディターを離れる必要はありません。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集をレビューして承認します。
- セッション中にエージェントへ指示を出し、ハイ コントラストに加えてライト モードの切り替えも追加します。

## シナリオ

[演習 4][previous-lesson] で使ったアクセシビリティのカスタム エージェントがハイ コントラスト モードを実装しています。作業中に、デザイン チームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライト モードの切り替えも追加します。新しい会話を最初から始める代わりに、現在のセッションに指示を出して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが実行する各手順、探索したファイル、実行したコマンド、提案する編集が表示されます。ファイル編集は差分と **Keep** / **Undo** の操作とともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールして各ツール呼び出しを確認します。ファイルの読み取りと編集、実行を求めるターミナル コマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインライン表示されます。
   - **Keep** を選択すると変更を承認します。
   - **Undo** を選択すると変更を元に戻し、エージェントに再度作業させます。
4. チャット上部の **Files changed** を開くと、セッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナル コマンドの実行など、ツール呼び出しの許可を求める場合があります。エージェントは一時停止し、**Allow** を確認します。許可するコマンドだけを承認してください。

5. ハイ コントラスト モードの実装が完了するまで待ちます。最後に、変更内容の概要が表示されます。

## エージェントにライト モードを追加させる

ハイ コントラスト モードができたら、同じ会話でライト モードの切り替えを追加します。同じチャット セッションを続けるため、エージェントは以前の作業のコンテキスト (変更したコンポーネント、スタイルの方針、設定したローカル ストレージのパターンなど) を維持します。

1. Copilot Chat の入力欄に次のフォローアップ プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントは以前の変更を確認し、ライト モードの追加を提案します。
3. 変更ごとに差分をレビューし、**Keep** または **Undo** を使います。
4. エージェントが希望と異なる方向に進んだ場合 (例: 切り替え UI の構造変更)、入力欄の横にある **Stop** ボタンで停止し、補足のプロンプトを送ります。

> [!TIP]
> 作業中のセッションに指示を出す方が、最初からやり直すよりも速くなります。フォローアップ プロンプトで調整 ("CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う")、方向修正 ("3 つ目の切り替えは追加せず、既存の設定パネルにライト モードを統合する")、範囲の拡張 ("両方の切り替えにキーボード ショートカットも追加する") などを依頼します。

## 作業内容全体をレビューする

変更をコミットする前に、エージェントが変更したファイル全体を簡単に確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更されたファイルをいくつか開き、差分を確認します。ARIA 属性、キーボード操作、セマンティック HTML、ローカル ストレージへの保存など、カスタム エージェントのアクセシビリティ パターンが反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードを使って、進行中のセッションを監視して案内しました。ファイル編集ごとにレビューし、変更を承認または取り消し、コンテキストを失わずにフォローアップ プロンプトで作業を拡張しました。

このレッスンでは、次のことを確認しました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を承認または取り消す。
- 作業中のセッションにフォローアップ プロンプトを送り、方針を案内する。

[次のレッスン][next-lesson]では、アクセシビリティ作業をプルリクエストとして公開し、このラボでローカルのカスタム エージェントが生成した変更をレビューします。
